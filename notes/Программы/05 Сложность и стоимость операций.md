# Сложность и стоимость операций

**Алгоритм** задаёт последовательность действий для получения результата. **Сложность** описывает рост требуемой работы или памяти с размером входа. Она позволяет отличить решение, которое выдержит увеличение данных, от решения с быстро растущими затратами.

Сначала задаётся размер входа: `n` элементов, `k` байт ключа, `h` уровней дерева. Если параметров несколько, их нельзя автоматически заменить одним: обработка `n` строк длины до `k` может требовать `O(nk)` работы.

## Что означает O

Запись **O(f(n))** задаёт асимптотическую верхнюю оценку: после некоторой границы работа ограничена постоянным множителем от `f(n)`. Постоянные множители и слагаемые меньшего порядка опускаются. **Θ(f(n))** задаёт совпадающий порядок верхней и нижней оценки, **Ω(f(n))** — нижнюю оценку.

Поэтому `3n + 20` имеет порядок `Θ(n)` и верхнюю оценку `O(n)`. Формально `O(n²)` тоже будет верхней оценкой, но менее точной. Буква O сама по себе не означает «худший случай»: нужно отдельно назвать, какая стоимость оценивается.

| Рост | Пример при оговорённых условиях | Для n = 1024, в условных шагах |
|---|---|---:|
| O(1) | Индексирование массива фиксированного размера элемента | Постоянное число |
| O(log n) | Сужение области поиска вдвое | Около 10 уровней |
| O(n) | Полный проход | 1024 |
| O(n log n) | Типичный эффективный алгоритм сортировки сравнением | Порядка 10 240 |
| O(n²) | Перебор всех упорядоченных пар | Порядка 1 048 576 |
| O(2ⁿ) | Перебор вариантов «включить/не включить» для n элементов | 2¹⁰²⁴ вариантов |

Это сравнение масштаба работы, а не расчёт времени в секундах. Вывод каждого подмножества отдельным списком дополнительно требует копировать его элементы.

## Как считать совокупную работу

Два последовательных прохода требуют `n + n` действий, то есть `O(n)`. Полный внутренний проход для каждого из `n` элементов даёт `O(n²)`. Но вложенность циклов сама по себе недостаточна.

Псевдокод поиска по неубывающим границам:

```text
left = 0
для right от 0 до n - 1:
    пока left <= right и условие нарушено:
        left = left + 1
```

Если обе границы только растут, `right` делает `n` шагов, а `left` суммарно не более `n`. При проверке условия за `O(1)` общая работа `O(n)`. Если проверка каждый раз просматривает всё окно, эта дополнительная работа изменяет оценку.

В [рекурсии](03%20Вызовы%20функций%20и%20стек.md) считают не только глубину, но и общее число вызовов. Два рекурсивных вызова на каждом уровне могут создать экспоненциальное дерево работы при линейной глубине.

## Худшая, ожидаемая и амортизированная стоимость

**Худший случай** ограничивает самый дорогой вход заданного размера. **Средняя стоимость** требует модели распределения входов. **Ожидаемая стоимость** может усредняться по случайным решениям алгоритма, например выбору хеширования. Без указания модели вероятностная оценка неполна.

**Амортизированная стоимость** распределяет затраты по последовательности операций и не требует случайного входа. У [динамического массива](06%20Массивы%20и%20связные%20списки.md) большинство добавлений дёшевы, но расширение копирует прежние элементы. При геометрическом увеличении ёмкости суммарное число копирований за `n` добавлений равно `O(n)`, поэтому добавление имеет амортизированную стоимость `O(1)`.

Это не гарантирует постоянной задержки отдельного добавления: оно может стоить `O(n)`. Для ограничений времени одного запроса важен именно такой дорогой шаг, а не только среднее по истории.

## Какая память считается

**Входная память** хранит исходные данные, **дополнительная** — рабочее состояние алгоритма, **память результата** — ответ. Эти категории полезно указывать отдельно. Алгоритм может использовать `O(1)` дополнительной памяти, но выдавать результат размера `O(n)`.

Рекурсивный стек тоже занимает память. Обход [дерева](08%20Деревья.md) в глубину использует `O(h)` состояния, где `h` — высота; для цепочки это `O(n)`. Представление маленького участка массива может быть небольшим, но [удерживать](04%20Время%20жизни%20и%20владение%20данными.md) большой исходный блок.

## Цена одной операции

Модель `O(1)` для сравнения и арифметики предполагает значения ограниченного размера. Сравнение длинных строк может просмотреть их байты; хеширование ключа длины `k` обычно требует `O(k)` при вычислении с нуля. Работа с целыми произвольной длины также зависит от числа разрядов.

Переход по ссылке и чтение соседнего элемента массива могут иметь одинаковую асимптотику, но разную стоимость из-за [локальности памяти](../Компьютер/04%20Оперативная%20память%20и%20кэши.md). Аллокации, копирование, синхронизация и ввод-вывод тоже не исчезают из-за короткой записи операции.

Асимптотика помогает выбрать подходящий рост затрат. [Измерение производительности](../Операционные%20системы/06%20Производительность.md) проверяет реальные задержки и объёмы при конкретных данных. Одно не заменяет другое: быстрый тест на маленьком входе не исправляет квадратичный рост, а лучшая асимптотика не обещает выигрыш при любом размере.
