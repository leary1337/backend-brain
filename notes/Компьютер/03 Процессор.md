# Процессор

**CPU**, центральный процессор, выполняет машинные инструкции: вычисления, обращения к памяти и переходы между участками программы. Его производительность зависит от выполняемой работы, доступности данных и организации вычислений.

## Инструкция, такт и частота

Для первой модели выполнение выглядит так: получить инструкцию → определить её смысл → выполнить действие → перейти дальше. Современный процессор совмещает этапы нескольких инструкций и может выполнять независимые операции параллельно внутри ядра.

**Такт** — шаг внутренней синхронизации. **Частота** показывает число тактов в секунду: 3 GHz означает 3 миллиарда тактов, а не 3 миллиарда любых законченных операций. Разным инструкциям требуется разная работа; ожидание данных и зависимости тоже меняют результат.

Поэтому частоту имеет смысл сравнивать вместе с архитектурой, нагрузкой и условиями работы. По одному числу GHz нельзя определить скорость обработки задачи.

## Ядро и логический процессор

**Ядро** — аппаратный исполнительный блок процессора. Несколько ядер позволяют действительно одновременно выполнять независимую работу.

**Логический процессор** — аппаратный контекст выполнения, который ОС видит как место для запуска потока. Технология SMT позволяет одному физическому ядру предоставлять несколько таких контекстов. У них отдельное архитектурное состояние, но общие исполнительные ресурсы ядра. Intel Hyper-Threading — один из вариантов SMT.

Например, 8 физических ядер с двумя контекстами на ядро дают 16 логических процессоров. Это не эквивалент 16 независимым физическим ядрам и не обещание двукратного ускорения.

**Поток ОС** — уже программная сущность: последовательность исполнения, которую планирует операционная система. Сотни потоков могут по очереди использовать несколько логических процессоров.

В виртуальной машине **vCPU** — предоставленный ей виртуальный вычислительный ресурс. Его наличие само по себе не доказывает постоянное эксклюзивное владение физическим ядром.

## Регистры, зависимости и ожидание

**Регистры** — небольшие хранилища внутри процессора для текущих значений, адресов и состояния выполнения. Для работы с большими объёмами данных нужны кэши и RAM.

Если следующая операция требует ещё не полученного значения, возникает зависимость. Например, при обходе цепочки записей адрес следующей записи становится известен только после чтения предыдущей. Дополнительные ядра не убирают такую последовательную зависимость автоматически.

Предсказание переходов помогает процессору заранее готовить вероятный путь после условия. Ошибка предсказания создаёт лишнюю работу. Это объясняет, почему одинаковое число операций в исходной задаче ещё не гарантирует одинаковое время на разных данных.

## Последовательная часть ограничивает ускорение

Учебная модель: задача занимает 1 секунду, из неё 0,2 секунды обязательно выполняются последовательно, а 0,8 можно идеально разделить между исполнителями.

| Исполнителей | Время без дополнительных расходов |
|---|---|
| 1 | 1 с |
| 4 | 0,2 + 0,8 / 4 = 0,4 с |
| Очень много | Предел — 0,2 с |

Даже в этой идеальной модели предел ускорения — 5 раз. Реальные координация, передача данных и конкуренция за память добавляют расходы.

## Что означает загрузка CPU

Загрузка показывает занятое процессорное время за интервал. Процент зависит от способа нормирования. В некоторых инструментах 100% процесса означает один полностью занятый логический CPU, и процесс может показывать больше 100%; на графике всей машины 100% могут означать все CPU.

Один полностью занятый CPU на машине с 16 логическими CPU даст среднее около 6,25%. Поэтому маленькая средняя загрузка не исключает, что одна последовательная задача уже ограничена процессором.

В Linux `lscpu` показывает видимую топологию: sockets, cores, threads, NUMA и кэши. В виртуальной машине это представление предоставленного оборудования; для контейнера отдельно учитываются ограничения CPU. Команда приведена для самостоятельной проверки, здесь не выполнялась.
